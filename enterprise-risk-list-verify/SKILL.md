# 企业风险名单核实与研判

拿到一份企业名单 CSV（尤其是从数据产品导出的"预警名单""团伙画像"）时，**先验证数据本身，再研判风险**。行业里这类表最常见的失败模式不是造假，而是"关键词模糊匹配 + 笛卡尔积展开"造成的名称-代码错乱。

## 第一步：信用代码校验位验算（秒级排雷）

用 GB 32100-2015 第 18 位校验码算法，能立刻判断代码是"真码"还是"随手编的"。

```python
CHARSET = "0123456789ABCDEFGHJKLMNPQRTUWXY"   # 31 位，无 I O S V Z
WI = [1,3,9,27,19,26,16,17,20,29,25,13,8,24,10,30,28]

def uscc_check(code):
    code = (code or "").strip().upper()
    if len(code) != 18: return "LEN%d" % len(code), None
    if set("IOSVZ") & set(code): return "ILLCHAR", None
    try:
        s = sum(CHARSET.index(code[i]) * WI[i] for i in range(17))
    except ValueError:
        return "ILLCHAR", None
    calc = 31 - (s % 31)
    if calc == 31: calc = 0
    exp = CHARSET[calc]
    return ("OK" if exp == code[17] else "BAD"), exp
```

**注意：校验位通过 ≠ 主体真实存在 ≠ 名称与代码对应正确。** 它只证明代码不是乱敲的，是必要不充分条件。

## 第二步：识别名称-代码错乱映射（P0 缺陷）

检查方法：
1. 统计每个信用代码出现在几个不同公司名下 → 出现 ≥2 次即为错乱
2. 统计每个公司名下挂了几个不同代码 → 同理
3. **关键判据：凡"法定代表人"和"注册资本"两列同时为空的行，几乎 100% 是模糊匹配噪声**

根因通常是：源数据用字号/关键词（如"XX银行""XX集团"）做模糊搜索，把命中集合以笛卡尔积形式展开到每个候选名称下。

再用**行政区划码（前 6 位）**做交叉验证：若代码属地与公司名中的地名矛盾，直接判为噪声。

常见区划码示例：510108 成都成华、510105 成都青羊、510106 成都金牛、510100 成都市、510000 四川省、511803 雅安名山、511826 雅安芦山、511800 雅安市、371425 山东齐河、650000 新疆、510181 都江堰、510600 德阳、511124 乐山井研。

## 第三步：主体核实

- **工商数据 API**（如企查/启信宝类 MCP 或开放接口）是首选通道，常用能力：
  - 工商基本信息查询
  - 按简称/关键词模糊归一，取 orgid/creditcode
  - 经营异常 / 失信被执行 / 被执行人 / 限高消费
  - 参控股穿透 / 最终受益人
- **坑：部分 MCP 会出现鉴权失效（401）**。遇到就说明情况，改用 WebSearch 多源交叉，不要卡住。
- WebSearch 技巧：直接搜 18 位信用代码，命中率高（百科/爱企查/启信宝/水滴页面标题常含代码）；再搜"公司名 + 经营异常/股权冻结"补风险维度。

## 第四步：壳群特征识别（判断"是不是团伙"）

命中 3 条以上基本可定性：

| 特征 | 说明 |
|---|---|
| 同日/相邻日批量设立 | 10 家同一天成立，代码连号发放 |
| 同一注册地址 | 同一楼层不同室号也算 |
| 0 实缴 + 0 社保 | 年报参保人数为 0 是最硬指标 |
| 认缴畸高且长期未实缴 | 单家数亿至数百亿，实缴为空 |
| 连续未报年报 / 住所失联 | 反复被列异，注意布尔值字段会掩盖次数 |
| 共用电话/邮箱 | "同电话企业 74 家"这类直接是团伙证据 |
| 循环交叉持股 | A 持 B、B 持 C、C 持 A，全部认缴 |
| 所属集团/族群 | 数据平台的"集团成员 N 家、集团风险 N 条" |
| 第三方空壳评级 | 启信宝"空壳指数 L5 高风险"等 |

**必查但名单里常缺的：共同股东、实控人穿透、社保人数、注册地址、集团归属。** 名单只给法定代表人是远远不够的。

## 第五步：实控人穿透

不要只看法定代表人。典型路径：
- 查注册资本最大的那家的股东结构
- 看是否有"某年某日法人变更 + 股权一次性归集至某人 95%"——这是**责任主体切换**动作，时间点要重点追溯
- 用第三方"疑似实控人""最终受益人"字段交叉验证持股比例

## 第六步：时间窗口分析

在老主体被冻结/列异/转税务非正常户之后，**是否仍在设立新主体**？是 → 换壳/资产平移信号，新主体法人要立刻纳入监控。

## 输出物

1. **HTML 研判报告**（light 主题、表格化）：核实结论 → 数据可靠性核验 → 分系列核实表 → 风险事件表 → 对比与分级 → 处置建议 → 方法与局限
2. **修正清单 CSV**（UTF-8 BOM，Excel 可直开）：系列 / 代码 / 核实名称 / CSV 原记名称 / 法人 / 认缴 / 成立日 / 地址 / 状态 / 已核实风险摘要 / 映射判定 / 处置建议。对无法确认的代码标"存疑"，不要硬塞进结论。

## 易踩的坑

- **字号像机构名 ≠ 是机构**：如"XX银行XX有限公司"里的"XX银行"可能是少数民族自然人姓名（看英文名是否音译、看法人的姓名是否与之相同）。反过来，第三方平台会按"银行"关键词打上"存贷款/金融理财"标签——**那是关键词误标，是数据污染**，别据此认定其从事金融业务。
- **同名自然人混淆**：人物库里同名不同人是常态，用任职企业代码/身份证区分，别合并。
- **实缴数据多源冲突**：有的源显示巨额实缴、有的为空，必须标注冲突并建议以官方登记为准，不要选一个就下结论。
- **布尔值风险字段**：`t1异常经营=1` 只代表"有"，会掩盖"被列异 4 次且已住所失联"这种关键升级信号。
